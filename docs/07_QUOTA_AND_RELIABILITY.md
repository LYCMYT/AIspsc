# 07｜额度、异步与可靠性

已确认的是“后台分配额度、无充值”。以下事务与取消政策为重建方案；不能当成已核验的旧源码实现。

## B1 模拟额度

初始账户 1286 个演示额度，每个模拟输出成本 1 个；这是测试规则，不是模型价格或人民币。
余额 UI 必须写“演示额度”，展示可用、预占、已消耗。B1 无管理员系统，使用本地测试夹具模拟 GRANT。
真正的管理员分配、鉴权、账本防篡改属于 B2，不能用浏览器 Store 充当生产财务账本。

## 额度生命周期

1. 先验证请求、文件、路由能力。
2. 可用额度足够时为每个子任务 RESERVE；不足则整个批次不创建，返回 QUOTA_INSUFFICIENT。
3. 子任务产物成功落盘并可访问后 COMMIT 一次。
4. 确定失败/未提交即取消时 RELEASE 一次。
5. 外部提交结果未知保留预占，进入 needs_reconciliation，不立即释放后又扣一次。
6. 人工认为生成画面不好不自动退款：模型已完成一次输出；再生成是新任务并重新报价。这是本次建议政策。

恒等式：累计授予 = 可用 + 有效预占 + 净已消耗（本版不开放手工扣回额度/负余额/真实退款）。
每条变更以 itemId+动作唯一约束；重复回调、刷新、重复点击都不得多扣、多退。

## 请求幂等

同 idempotencyKey + 同 requestHash 返回已有 batch；同 key + 不同 requestHash 返回 409 IDEMPOTENCY_CONFLICT。
B1 在持久化服务内实现；B2 在事务中以唯一键保护，不只靠按钮禁用。
UI retry 会产生新的幂等 key；网络重发沿用原 key。

## 外部结果不确定

HTTP 超时不能自动推断 Provider 未受理。
已获得 externalJobId：查询同一个外部任务；有供应商幂等功能时使用稳定外部幂等 key。
提交超时且没有可查询 ID/幂等接口：保持 unknown，人工或供应商对账；不能自动重发有费用的创建请求。
轮询/下载等可重试操作与创建付费任务分开处理。Adapter 不伪造不存在的取消/查询能力。

## B2 最小可靠性结构

PostgreSQL 同事务写入批次/子任务、额度预占和 Outbox。
Dispatcher 投递队列；Worker 消费并执行；业务状态和唯一约束承受至少一次事件，不依赖队列宣称端到端 exactly-once。
轮询与回调收敛到本平台状态；终态与额度变更同事务完成。
生成产物暂时下载失败只重试抓取/持久化，不再次调用生成。

前端查询本平台 task API，不持 Provider Key；前端关闭/刷新不取消后端任务。SSE 是可选优化，首轮真实后端先可靠轮询。
前端状态更新必须校验 itemId、版本/更新时间，不能让过期回调把 succeeded 改回 running。

## 取消

queued 可直接取消并释放预占；已提交外部的任务先 cancel_requested。
只有供应商确认取消或对账确认未产生可结算结果，才按取消策略收敛；若已成功，则按真实结果结算并提示不能撤回。
B1 可用可复现模拟场景演示取消竞争；不要对所有真实 Provider 承诺“点击即成功取消”。

## 故障用例必须覆盖

重复提交、部分失败、Worker 崩溃恢复、重复事件、供应商超时未知、对象存储写失败、额度不足、取消与成功竞争、刷新/重开、多标签页。
B2 每个账户/工作区必须有隔离、上传限制、队列并发上限、密钥保护；公网部署前需完成鉴权与文件授权读取验收。

## 本次范围内的计费边界

B1 每一个生成输出统一 1 演示额度，图片/文案同样遵循；查看历史、人工审核、入库、下载和视频拆解不扣生成额度。
这是一套明确的重建测试政策，不是原业务定价。B2 可先保留测试政策；B3 接入前必须建立真实定价版本及成本核对，不使用 Demo 单价上线。
B1 多标签页通过 IndexedDB readwrite 事务更新同一命名空间内任务、预占和流水；不能依靠每个标签页各自的内存锁。
