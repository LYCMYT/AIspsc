## Gap Analysis

There is no HTTP `DemoPlatform`, server generation aggregate, persistent server job queue or HTTP command validation. Several existing facade mutation signatures omit an optimistic version, so the adapter must supply one without changing the UI contract. HTTP inputs cannot rely on TypeScript casts. Durable publication must atomically include items, reservations, attempts and pending work. A worker must run without `pump()`, open pages or HTTP poll requests. Review revisions and manual-save operations must share the same version and transaction protection as cancellation.

## Proposed B2.1A Architecture

```text
Vue / unchanged ServiceFacade
  ├─ production and default development → MockPlatform / IndexedDB
  └─ development mode local-http → HttpPlatform
       → same-origin /api proxy (operator token added by Vite server)
       → loopback Node HTTP adapter
       → GenerationService + pure domain reducers
       → serialized file snapshot: aggregate + quota + attempts + pending + memo
                                 ↑
                         timer-driven FakeWorker
                                 ↓
                         hash-verified local fixture files
```

Use the existing Node/Vite/TypeScript/Ajv/Vitest stack without adding dependencies. Node HTTP is a thin transport for this controlled local slice. NestJS modular monolith, PostgreSQL, object storage and a separately deployed Worker remain the later architecture; this timer is a separate module in the same process, not a distributed worker or a production queue. The existing domain import graph uses bundler resolution and JSON imports; the development launcher uses existing Vite `ssrLoadModule` rather than pretending the whole graph already runs under native Node TypeScript resolution.

### Precise shared HTTP contract

Add `packages/contracts/src/http.ts` and export it from `index.ts`. JSON responses use the existing `Result<T>`. All input objects reject unknown properties. Idempotency headers use `Idempotency-Key`, with a nonempty 1–100 character `[A-Za-z0-9_-]` value. Item mutations require a nonnegative safe integer `expectedVersion`, including first review, revised review, manual save, retry, cancellation, reconciliation and download recovery.

```ts
export interface ItemVersionInput { expectedVersion: number }
export interface ItemReviewInput extends ItemVersionInput { form: ReviewInput; reason: string }
export interface ItemSaveInput extends ItemVersionInput { evaluationId: string }
export interface ItemReconcileInput extends ItemVersionInput {
  outcome: 'success' | 'failure' | 'cancelled';
}
export interface FixtureLoadInput { key: string }
export interface ScenarioInput { name: ScenarioName }
```

The local scenario endpoint changes the default for future fake jobs, never rewrites existing jobs or seeds/reset history. Supported names: `seed`, `empty`, `processing`, `success`, `failure`, `partial_success`, `unknown`, `download_failure`, `cancel_race`, `quota_insufficient`, `request_failure`, `storage_failure`. `missing_file` is explicitly unsupported in HTTP mode. `processing` means delayed deterministic success, not an eternal job. Unknown-outcome resolution is explicitly synthetic operator evidence, not Provider reconciliation evidence.

Map invalid JSON/schema/version omission to 400 `INVALID_PARAMETERS`; unauthorized access to 401 `FORBIDDEN`; hostile Host/Origin to 403 `FORBIDDEN`; absent tasks/media to 404 with existing `TASK_NOT_READY` / `MEDIA_UNAVAILABLE`; version/idempotency and state conflicts to 409; unsupported capabilities to 422 `NO_COMPATIBLE_MODEL`; oversized JSON (64 KiB) to 413; storage failures to 503 `STORAGE_UNAVAILABLE`. JSON error responses contain only safe fixed messages/codes, never request bodies, tokens, absolute paths or signed URLs.

### State and transactions

The server-owned `GenerationState` extends the public snapshot with `sequence`, `pending`, `memo` and `reviewForms`. Pending jobs include `itemId`, `dueAt`, captured `scenario`, phase and download-retry flag. Memo records are keyed by operation scope + idempotency key and retain canonical payload hash plus the accepted response. Review storage binds immutable form/reason to evaluation id and current result SHA-256 (copy uses a digest of its exact text). Public snapshot projection omits memo, private forms and scheduling internals.

Canonical JSON recursively sorts object keys, preserves array order and trims the generation prompt. Create hashes the normalized request; retry additionally binds the original item id. Mutation hashes include expectedVersion. A matched successful replay returns its original accepted result before checking today's version; a different payload under the same scoped key returns conflict. Failed commands are not memoized. An independent new key with an old version always conflicts, even if its requested operation is a terminal no-op. Every successful new item mutation increments that item's version exactly once; a retry increments its source item's version while creating a new single-item batch with `retryOfItemId`.

Use `GenerationStore.transact<T>((state) => Result<T>): Promise<Result<T>>`. Clone the current state, run synchronous domain work, persist a fully valid new snapshot, then publish the clone in memory. On validation/domain/persistence failure neither state nor quota is published. All writes are serialized; one exclusive `.lock` prevents two service processes sharing a directory. Temporary file is fsynced before atomic rename. Read data is detached. Corrupt state fails startup, not reset. Graceful shutdown stops the timer, drains work and releases its owned lock; stale locks require operator confirmation that the old process is gone. Storage paths are supplied only by server configuration; use realpath/containment and reject symlink escapes for fixture/store paths.

The create transaction includes batch, items, attempts (`not_submitted`), reservations, pending work and memo. Finalization commits result metadata, success state, quota COMMIT and removal of pending work together. Copy text is stored as text, not a media Blob. Known failure/cancellation releases once; unknown and recoverable finalizing retain the reservation. State validation checks references, ids, statuses, versions, quota equality and unique item/action ledger entries on reload.

### Pure reducers and fake worker

Place shared HTTP-state types in contracts; put deterministic aggregate reducers in focused domain modules for creation, lifecycle and review/library. Inject clock/IDs/fixture metadata; do not import filesystem, HTTP, browser or Provider code into these reducers. Reuse the existing primitive state/quota/review functions. Avoid moving or rewriting the functioning B1 service just to share implementation.

`FakeWorker.tick()` processes persisted due jobs; `start()` schedules ticks and `stop()` drains them. No reentrant tick. Fake submission persists `submitting`, then stable fake `externalJobId` and `submitted`; restart resumes the same item/attempt rather than creating another. Fake outcomes depend only on captured scenario/index, never randomness. `partial_success` fails indices where `index % 3 === 1`; cancel-race succeeds after cancellation request; unknown blocks until explicit synthetic reconcile; download/storage failure pauses finalizing until explicit download retry and never creates another generation attempt. Worker candidate writes compare captured item versions inside the transaction and discard obsolete work.

Media is chosen by existing fixture keys (`video-{seconds}-{ratio x}-{resolution}-{audio|silent}`, `image-{ratio x}-{resolution}`). Manifest capability existence is checked before accepting the batch; unsupported combinations fail without reservation. Before review/success, read bytes and verify SHA-256 against the manifest and recorded actual metadata. Fixed files are read-only; file bytes live outside JSON and metadata uses controlled relative `objectKey`, never base64 or signed URLs. Responses mark `isDemo=true` and fixture linkage; the existing UI's “演示视频” indication remains visible. Uploaded and imported sources are not invented by this service.

Review uses runtime-validated `ReviewInput`, current verified media/text and `decideReview`. The first approval creates no asset. A later review requires a nonempty reason, creates a new immutable revision, increments item.version, invalidates previously saved assets and sets item.libraryState to `not_saved`, even when approved again. Manual save requires the newest approved evaluation with matching result digest. Maintain one asset per origin item; a new explicit save may rebind that asset to the new approved evaluation while retaining review history. Generation using invalidated, archived or unavailable assets fails validation. Raw history media remains viewable for re-review; raw history media access does not represent library approval.

### HttpPlatform and local security

`HttpPlatform implements DemoPlatform` in a dedicated browser-safe package. Keep facade signatures unchanged. Cache last-observed item versions from snapshots/get/create/mutation results; when no version is known fetch the item once. An explicitly supplied cancel version wins. Send captured versions for all commands; never fetch-and-retry after 409. Keep command key/body on ambiguous network failure for identical retries; creation/retry honor the caller's key. Protect snapshot ordering using request sequencing and never regress a cached item to a smaller version. `ready()` reads a snapshot; `snapshot()` reads HTTP; `pump()` is a no-op and never executes or triggers server jobs. `media.get()` fetches metadata + binary and returns `{media, blob}`; existing UI manages object URLs.

Peripheral uploads, restore, asset metadata editing/deletion, media put/remove, splitting/clip-save and reset explicitly return `FORBIDDEN` with a local-mode unsupported message. There is no in-memory or Mock fallback. Fixture loading, generation/history/recovery/review/manual-save/quota are implemented end to end.

Select HTTP only when `import.meta.env.DEV && import.meta.env.MODE === 'local-http'`. Production builds, including `--mode local-http`, select Mock and contain no server token or Provider runtime. Run the development launcher with random operator token retained in server memory, start the API at `127.0.0.1:8788`, then start Vite at `127.0.0.1:5173` in local-http mode with server-only proxy configuration. The browser fetches `/api/v1/...` with no credential secret. The proxy validates exact loopback Host and matching Origin before injecting Authorization; rejects hostile `Origin`, Host and cross-site Fetch Metadata, forwards the original allowed Origin, rewrites `/api` and API Host. API independently validates bearer token, exact Host and configured allowed local Origin (absent Origin allowed for token-authenticated CLI). No permissive CORS. Do not log or expose token/config endpoints. Tests use injected tokens without printing them. Bind both listeners to loopback and prohibit public deployment/tunnels.

## Exact Files / Test Strategy

The companion plan is authoritative for file ownership and four reviewable tasks. Tests execute contracts and real local HTTP behavior, not regex assertions against source text. Cover canonical replay/conflicts, every item mutation's version handling, store lock/corruption/rollback/restart, quota invariants, autonomous fake execution, partial failure, cancellation race, unknown reconciliation, download recovery, all three modalities, review revision/invalidation/manual save, binary hash/playback, adapter errors/no fallback and hostile Host/Origin. Retain every existing CI gate. Record actual commands, commit, exit codes, test counts and screenshots in local evidence; generated evidence remains ignored.

## Risks and Explicit Non-goals

File persistence is a bounded single-process development service. It is not PostgreSQL, a transactional distributed outbox, authentication/workspace isolation, HA, or production billing. Timer-worker interruption is recoverable because fake work is deterministic; this does not prove safe real paid-create retry. Immutable fixture bytes are a deliberate local media delivery compromise, not object storage. Automatic media interpretation, arbitrary uploads/FFmpeg, real Provider calls, Agnes integration/routing promotion, payments, new models, public deployment, push/merge and modifications to the delivery workbench are outside B2.1A. No business quality, marketing conversion or historical customer data is inferred from synthetic tests.
