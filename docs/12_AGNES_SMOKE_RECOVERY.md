## 故障如何处理

### 结果完成不等于本地交付完成

首次调用的真正断点是结果地址解析，不是生成失败。修复只读取已确认的 `metadata.url` 或顶层 `url`，不递归搜索输入图片等无关 URL。

原始 opaque `video_id` 保持不变，不使用查询响应中的另一个 upstream `id` 替换。

### 文件域名与示例不同

先只读诊断真实域名，再精确加入允许列表。只允许文档域名及实测域名，不使用通配域名，不跟随下载跳转，不把 Provider Authorization 传到媒体存储域名。

### 可恢复状态与隐私

创建前保存提交意图，取得 ID 后立即保存。轮询/下载失败也保存 ID 与阶段；`recover` 分支只 GET，不再次 POST。

结果文件进行 MIME、大小上限（128 MiB）、MP4 头、ffprobe 元数据与全片解码检查。异常仅记录安全错误码，不保留可能含签名地址或密钥的原始异常原因。

## 产品参数阻塞项

1. **比例与尺寸**：1280/704 并非严格 16/9。不能偷偷拉伸或裁剪商品；后续需明确补边/裁剪策略并保留原文件。
2. **音频**：此前从“文档没有音频开关”推导“无音频输出”不成立。`audio=false` 未传入 Agnes（模型文档没有该参数），输出仍有音轨。后续无音频要求应显式移除音轨并复验；也不能据此宣称支持可控原生音频生成。
3. **时长**：实际 121 帧为约 5.04 秒；需要确定允许误差或后处理规则，不能把 API 的整数 seconds 当文件事实。
4. **成本**：文档当前 $0/秒不等于账户账单已核验。`actualCostUsd=null` 保留。
5. **范围**：10 秒、竖版、方图、1080p、参考视频、多参考仍未完成实测。

## 后续实施顺序

先做明确、可验证且不重新消耗模型额度的输出规范化，再做最小服务端闭环（密钥隔离、任务持久化、受控访问、下载复验、审核入库）。不要直接把密钥放进 Pages，也不要把两个技术样本包装成生产上线。
