# 00｜项目概览

## 项目定位

**多模型 AI 营销视频生产平台**面向电商投流素材生产，把“准备参考素材 → 描述创意 → 生成 → 等待 → 人工判断 → 重生成 → 整理 → 复用”的碎片化操作，重构为一个可追踪、可审核、可恢复、可复用的 AI 内容生产工作流。

本仓库不是原商业生产源码，而是基于已确认业务规则、产品流程和工程约束重建的**公开可复验 Demo**。当前实现停留在 **B1 本地交互式模拟层**：核心产品行为可以真实操作和测试，但不会调用外部付费模型，也不包含生产后端、账号鉴权、真实计费或客户环境。

## 要解决的核心问题

传统 AI 素材生成工具往往把复杂度直接暴露给用户：用户需要研究模型、参数和兼容关系，同时还要自己处理等待、失败、重试、审核和素材归档。对真实业务团队而言，问题并不只是“能不能生成一条视频”，而是：

1. **输入是否标准化**：Prompt、商品、人物、背景、参考视频如何形成稳定任务合同。
2. **能力是否可路由**：不同任务需要什么模型能力，不能靠用户猜测模型兼容性。
3. **异步任务是否可靠**：批量结果可能部分成功、失败、取消、超时或状态未知。
4. **质量是否可管理**：生成成功不等于业务可用，必须经过人工审核并留下版本证据。
5. **资产是否可复用**：审核通过与进入资产库必须分离，避免未经确认的结果污染素材库。
6. **成本是否可追踪**：付费任务需要预占、结算、释放和幂等，而不是只显示一个余额数字。

## 当前 B1 已实现的产品闭环

```text
参考素材 / Prompt
        ↓
严格请求校验
        ↓
任务分类与 Mock 能力路由
        ↓
Generation Batch / Item
        ↓
异步状态推进与故障场景
        ↓
生成历史
        ↓
逐条人工审核
        ↓
approved / rejected
        ↓
手动入库
        ↓
资产复用
```

同时提供独立的视频拆解与素材管理能力：

```text
源视频
  ↓
顺序 / 平均 / 场景 fixture / 手动区间
  ↓
合法区间与真实浏览器预览
  ↓
仅在已有真实切片文件时允许下载或复用
```

## 五个真实可操作入口

| 入口 | 当前能力 | B1 边界 |
|---|---|---|
| 创作 | 视频 / 图片 / 文案；Prompt；参考视频 / 人物 / 商品 / 背景；参数与数量 | 生成结果由确定性 Mock 产生 |
| 历史 | 批次与子任务、部分成功、取消、重试、未知状态对账、审核、手动入库 | ProviderAttempt 为模拟证据 |
| 资产库 | 上传素材、生成后入库素材、来源与可用性管理 | 浏览器 IndexedDB 持久化 |
| 视频拆解 | 顺序、平均、固定场景边界、手动区间、帧预览 | 任意上传视频暂不在服务端真实渲染切片 |
| 素材识别 | 固定样例标签 + 人工标签 | 未执行真实 AI 识别，不伪造语义结果 |

## 关键产品原则

- **用户表达意图，不要求用户选择底层模型。** 前台没有 `modelId` 或“参考强度”控件。
- **生成、审核、入库是三个独立步骤。** 成功结果先进入历史，审核通过后仍需用户再次确认入库。
- **批次和结果分层。** `count > 1` 时逐条维护状态、错误、审核和额度，允许 `partial_succeeded`。
- **未知结果不等于失败。** 外部提交结果不确定时进入 `needs_reconciliation`，不自动重复创建可能产生费用的任务。
- **来源不可混淆。** 上传素材、生成结果和固定 fixture 保留不同 provenance。
- **没有执行就明确写未执行。** 未知上传不会获得虚构 AI 标签、场景边界或下载链接。

详细决策见 `docs/01_PRODUCT_DECISIONS.md`。

## 评测与人工审核

视频结果使用 `rubric-v2-rebuild`：11 类质量维度、适用性、硬失败、技术失败和 1–10 综合人工分。当前量表是基于已确认业务需求重建的审核合同，**不是原历史评测数据的逐字恢复，也不宣称阈值已经过真实样本统计验证**。

B1.5 将在不扩大无谓生成成本的前提下补充小样本真实模型实验，并把“文档证据、Smoke Test、真实评测、正式接入”严格区分。

## 版本路线

### B1｜Local Interactive Simulation（已实现）

验证核心工作流、状态合同、审核、额度、拆解和浏览器持久化；不产生真实 Provider 成本。

### B1.5｜Portfolio Evidence Release（当前阶段）

目标不是继续堆页面，而是补齐：

- 产品背景与关键决策；
- 系统架构与边界；
- 模型能力证据状态；
- CI 独立复验；
- 小样本真实模型评测与 Bad Case 复盘；
- 可公开展示的项目证据链。

### B2｜Real Platform Foundation（计划）

引入 HTTP API、Workspace/Auth、PostgreSQL、对象存储、真实 FFmpeg、服务端账本、Outbox/Worker 和授权访问控制。

### B3｜Real AI Provider（计划）

在完成官方接口核验、预算授权和 Smoke Test 后，引入 Provider Adapter、真实异步任务、真实成本与模型能力路由。

### B4｜Production-like Acceptance（计划）

补充客户级验收、安全、可观测性、限流、Provider 健康度与故障切换等生产约束。

## 不在当前仓库声称完成的事项

- 真实 Provider 调用与模型质量保证；
- 生产 HTTP 后端；
- 登录、RBAC、Workspace 隔离；
- 真实充值/支付；
- 广告平台投放连接；
- 任意上传视频的服务端 FFmpeg 切片；
- 客户生产验收；
- 广告转化率或真实运营指标。
